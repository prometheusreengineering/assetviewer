# Asset Viewer — working notes for Claude

Unofficial fan viewer for Lunar Client cosmetics, served from `https://textures.lunarclientcdn.com` (CORS `*`), and Dawn Client cosmetics from `https://assets.dawn.gg/assets/` (no CORS: proxied, see Dawn below). Vue 3 + Vite 8 + vue-router (hash history) + PrimeVue 5 (Aura, `.app-dark`) + three.js 0.186. There is no top bar: the sidebar (in `ProviderView.vue`) holds the big provider switcher (`ProviderSwitch.vue`, a popover with multiline options; Lunar Client / Dawn Client / Essential, the last read from the viewer's own files, see Essential below), the category menu, and at the bottom `SideControls.vue` (player name + theme). `/#/lunar` (and `/#/dawn`) redirects to the `home` pseudo-category (`HomeView.vue`: text only — a short description, the Prometheus Reengineering line, credits; host/owner/credits come from the provider's `about`, which also feeds the footer disclaimer), which is not in `provider.categories()`; the menu adds a Home entry before Everything.

## Rules
- **Essential: never commit or deploy any of its catalog, asset files, file hashes or asset URLs** (DMCA). It is read only from the viewer's own disk at runtime. Test fixtures are synthetic (made-up ids, `cdn.example` URLs); real-data checks stay local (`ESSENTIAL_DUMPS`, scratchpad scripts). Before pushing Essential work, grep `dist/` and the repo for `cdn.essential.gg` and real ids.
- **`.env` holds `PRIMEUI_LICENSE`.** It must stay git-ignored. Never print, echo or commit it. (It ends up in the built JS; unavoidable for a client app.)
- Commit trailer: `Co-Authored-By: Claude <model> <noreply@anthropic.com>` naming the model actually in use (e.g. `Claude Opus 5.5`); follow the attribution reminder in the session if one is given. PR bodies end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- Only commit/push when asked. The user typically says "commit and push"; commit locally and offer to push otherwise.
- Pronouns: they/them unless stated.
- Shell is Windows (Git Bash/PowerShell). Use Unix syntax in Bash. Don't run `sleep` chains in the foreground.

## Commands
- `npm run dev` (vite; I use `npx vite --port 5199`), `npm run build` (= `vue-tsc -b && vite build`). The build always prints a >500 kB chunk warning (known, ignorable).
- Type check alone: `npx vue-tsc -b` (silent = pass). `erasableSyntaxOnly` is on: no class parameter properties.
- `node scripts/coverage.mjs` — classifies every CDN index file as item / dependency / resource and must print `UNCLAIMED 0` (exit 1 otherwise). Run it after touching `lunar/catalog.ts`. The logic lives in `scripts/coverageLib.mjs` (`classify()`), shared with the live test.
- `taskkill //F //IM node.exe` stops stray dev servers/CDP runs (Git Bash needs the double slashes).
- Tests (Vitest 5, `vitest.config.ts`, three projects): `npm test` runs everything; `npm run test:unit|test:dom|test:browser` one project; `npm run test:coverage` writes `coverage/` (git-ignored); `npm run test:watch`. One-time setup: `npx playwright install chromium`. CI: `.github/workflows/test.yml` (type check + all tests + coverage) on push/PR to main.

- **dom** (`tests/dom`, happy-dom): stateful modules (fresh import per test via `vi.resetModules`, they read localStorage on import), Vue components mounted with PrimeVue + a memory router (`tests/helpers/mount.ts`: `mountApp`, `settle`, `$`/`$$`/`byText`, `press` for PrimeVue's pointer events), and the whole app on the fixture CDN (`tests/dom/app.test.ts`). WebGL is faked with `vi.mock('three', …)` → `FakeWebGLRenderer` (`tests/helpers/webgl.ts`; it must not import `three`, or the mock factory deadlocks). `FakeIntersectionObserver.intersectAll()` makes cards visible.
- **browser** (`tests/browser`, Chromium via Playwright): real WebGL pixel checks (`readPixels` right after a render; `SharedRenderer.frame` is called directly), Cache Storage, live models, the full app on the hash router.
- Dawn: `tests/fixtures/dawn.ts` (one entry of each kind) served by `installDawnCdn` under `/dawn/...`; it delegates other URLs to the fetch installed before, so `installCdn(LUNAR_FULL)` first gives the outfit tests Lunar's player body. `tests/fixtures/images.ts` has `avif()` headers and a real `animatedGif()` (ImageDecoder decodes it in Chromium). The worker proxy is tested in `tests/unit/dawnProxy.test.ts`.
- Fixtures: `tests/fixtures/lunar.ts` is a mini CDN (every entry kind, unlisted files, resources, emotes, particles); `installCdn(LUNAR_FULL)` (`tests/helpers/cdnMock.ts`) serves it through a mocked `fetch` (both indexes + `/file/<hash>`, Range supported). `installBitmapStubs()` gives Node a `createImageBitmap` that reads sizes from image headers and a recording `OffscreenCanvas`. `installMemoryCaches()` is an in-memory Cache Storage (live tests).
- Some private helpers are exported only for tests (`ownerOf`, `enrich`, `measurable`, `dragonWingGeo`, `faceRects`, `buildCube`, `curveValue`, `hex`, `evalChannel`, `grow`, `socket`, …). Pin a known bug with `it.fails` (it flips to a failure once fixed; then make it a plain `it`).
- PrimeVue overlays teleport to `body`; the dom setup unmounts components (`enableAutoUnmount`) and then clears `body` after each test (afterEach hooks run last-registered first).

## Architecture
- `src/cdn.ts`: `getIndexBuffer`, `getFileBuffer/Json/Text(hash)`, `fileUrl(hash)`. Everything on the CDN is content-hash addressed, so results are stored in Cache Storage forever (`assetviewer-cdn-v1`) with a retry/backoff fetch. **Always get bytes through this cache** (see CORS notes).
- `src/providers/types.ts`: `CosmeticProvider` interface (`categories`, `fields(category)`, `items`, `imageUrl`, `loadModel`, `rawFile`, `indexedFiles`, `fileItem`, `ensureDimensions`, `info`, `stats`). `CosmeticItem.fields` is the bag the filter/sort bar reads; `name` is read from `item.name`.
- `src/providers/lunar/catalog.ts` builds the catalog from the two root indexes (`LUNAR_INDEXES` in `config.ts`; text lines `path sha1 size mtime`): `cosmetics.json` (primary), the legacy CSV `cosmetics/index` (fills gaps, typo'd ids), badges/sprays/emotes/particles/misc as "resources", and any unlisted cosmetic files found by scanning, plus one `emote` entry per `emotes/emotes.json` emote (category `emotes`; pushed without claiming paths so the emote files stay listed as resources). `Kind` = `gek | obj | wing2d | cloak | emote | image | file`. `CosmeticItem.thumb` ('image' | 'none') lets a 3D item (emotes) show its icon/name on the card instead of a live model.
- `src/providers/lunar/index.ts`: the provider. `loadGek` (Bedrock `.geo.json` + `.anim.json` + texture), `loadWing2d` (flat wing webp on `simple_2d_wings.geo.json`), `loadCloak` (22×17 OptiFine cape layout, scaled by any integer; stacked frames for animated), `loadObj` (legacy OBJ hats). `enrich()` adds id/path/folder/ext/size/type/model fields; `ownerOf()` maps any file path to its owning item (used by All files). Dimensions are measured lazily from file headers via Range requests (`src/dimensions.ts`). `loadModel(item, { raw: true })` skips `fitObject` (player-space blocks) for dressing a player; `sourceFiles`/`estimateSize` feed the ZIP export; `itemById` serves deep links/collections.
- Emotes (`lunar/emotes.ts`, `three/bobj.ts`): McHorse "Blockbuster OBJ" text. `arm_bone name parent tailX tailY tailZ <16 floats row-major head matrix>` (root parent is an empty token: split on single spaces), `o/v/vw/vt/vn/f` skinned meshes (OBJ indices are file-wide; flip `v`), actions `an/ao/ag location|rotation|scale axis/kf tick value BEZIER|LINEAR|SINE|CONSTANT lx ly rx ry` in ticks (20/s). Pose = `inv(parent.mat)·mat · T · R(Euler 'ZYX' = Blender XYZ) · S`, bones written to `bone.matrix` (matrixAutoUpdate off) and bound as a three `SkinnedMesh` (bind matrix identity, bones under the body mesh). Body = `emotes/models/entity/default.bobj`; emote `x` plays action `emote_x`, found by scanning the 9 actions files (one is 16 MB; `extractAction` slices one block); props from `emotes.json.props` **plus `props.bobj` (missing from that list)**, textures from `emotes.json.meshes` **or `entity/default.json` meshes** (popcorn); `meshes[].show_at` = tick a prop appears. `LoadedModel.timeline` drives play/pause/scrub.
- Emote particles (`three/particles.ts`, `emoteEffects` in `lunar/emotes.ts`): an emote's `morph` names an entry in `particles/configuration.json` whose `morphs[]` give `{Scheme:"x"}` (a Bedrock `particles/schemes/x.particle.json`), a player bone, `start`/`length` (ticks) and a translate/rotation/scale; `particleEffect` (make_it_rain) uses the scheme's own bone. `Emitter` simulates one scheme (steady/instant rate, point/disc/sphere/box shapes, dynamic/parametric motion, flipbook UVs, tint gradients, catmull-rom curves, Molang via `molang.ts` with `variable.particle_*`/`emitter_*`) and draws camera-facing quads with a tiny shader (offset scaled by the object's scale; sizes are half-extents). Texture `textures/particle/particles` = `particles/textures/default_particles.webp` (128x128; `emotes/textures/particles.webp` is a 78-byte stub). Particles are children of `player.object` and follow bones via `bone.matrixWorld`; jumps/loops of the emote tick reset them.
- Player (`three/player.ts`, `lunar/dress.ts`, `src/skin.ts`): the emote body in blocks. `dressPlayer(items, emote?)` adds raw cosmetics and "sockets" every gek group named `biped(Head|Body|RightArm|LeftArm|RightLeg|LeftLeg)*` under the matching player bone (a fixed holder reproduces its rest parent, so gek animations keep working; arm/leg side chosen by pivot x since some models mirror). Cloaks use `CAPE_ON_PLAYER` (bone `bipedBody`), OBJ hats/bodywear are placed by a heuristic (head/chest center, hats fully above center lifted onto the head). Skin: procedural placeholder, or `https://mc-heads.net/skin/<name>` (CORS *), persisted `assetviewer.skin`. It is one global "Player name" input at the bottom of the sidebar (`components/SideControls.vue`); the modal and the outfit builder watch `skinName` and redraw.
- **Dawn Client** (`src/providers/dawn/`): `assets_index.json` is a JSON array of `{ name, hash (sha1 of the content), url }`, no sizes or display names. The CDN sends no CORS headers, so the browser fetches `/dawn/<path>?h=<sha1>` (same origin): `worker/dawnProxy.ts` in production (allow-listed paths, Range, edge cache keyed by the hash, immutable), the Vite `server.proxy['/dawn/']` in dev and in browser tests. The index itself is network-first (`getFreshBuffer`), files go through `getUrlBuffer` (Cache Storage forever, the hash is in the URL). `catalog.ts` (`buildDawnCatalog`, pure) claims every file once: `geo` (own `.geo.json` + texture, optional `.animation.json`/`.meta.json`), `variant` (texture-only colour variant borrowing a sibling's geo+anim, `variantScore` on camelCase words), `cloak` (OptiFine 22x17 x16, drawn with Lunar's `CAPE_GEO`/`CAPE_ON_PLAYER`), `shield` (texture-only, on `shields/rectangleShield320.geo.json`), `trim` (one item per `<trim>_<slot>` set on the shared `trim/<slot>.geo.json`), strays in the wrong folder join the same-named model, `image` when nothing fits, `file` for shared models/lang/unknown. Names: `humanize` of the camelCase file name; `collection` = shortest shared leading words (extended over a year / words all share); items sorted by name. Models are standard Bedrock geo rooted at `anchor_head|body|rightarm|leftarm|rightleg|leftleg` + GeckoLib animations keyed `animation.<model>.<state>` (`normalizeAnims` keeps the state, drops the empty `null`). Same handedness as Lunar geks (`flipU`, `scale.x/z = -1` in prep). The field is `hasAnimation`, never `animated` (that makes the UI read stacked mcmeta frames). Dressing reuses `lunar/dress.ts` (anchors -> player bones; shields `LEFT_HAND`, a guessed pose) on Lunar's player body (`lunarHashOf`).
- **Essential** (`src/providers/essential/`): no public index; the Prometheus patch dumps each cosmetic to `.minecraft/prometheus/essential/dumps/<CATEGORY>/<ID>.json` (minified `Cosmetic`: `a` id, `b` category, `c` names by locale, `h` tags THEME_*/COLLECTION_*/flags, `m` slots, `o` price, `p` rarity, `q` files `path -> { a: url, b: sha256 }`), and Essential caches files in `.minecraft/essential/cosmetic-cache/<h0>/<h1>/<h[2:]>` (named by sha256). `localData.ts`: a `DirSource` over a `showDirectoryPicker` handle (remembered in IndexedDB via idb-keyval, `assetviewer.essential.dir`; Reconnect needs a click), `<input webkitdirectory>` files, or memory; `resolveFolders` finds both under `.minecraft`; `assetBytes` reads the cache, else downloads the URL from the viewer's own dump (CORS *) and checks the sha256. `catalog.ts` (pure) builds items; colour variants are `variants/<name>/texture.png` (order and default from `settings.json` VARIANTS), models `geometry.steve.json` (Bedrock, parts under a `root` bone: head/body/arm_*/leg_*/cape), `animations.json` (default state = the IDLE trigger's animation). Emotes, effects and icons are name tiles (group "Emotes & effects", not outfit slots). The provider's `setup.needed()` makes ProviderView show `EssentialSetup.vue` until connected; `LoadedModel.variants/setVariant` feed the modal's Colour select (swaps the texture image in place). Dev only: `window.__essential` (`connect`, `listingSource`, ...) lets headless checks connect a source (the native picker can't be clicked); serve the folders with a small local static server, not Vite's `/@fs/` (it transforms extension-less files). Not done yet: emotes on the player, particles, sounds, emissive layers, skin masks, `EXTERNAL_HIDDEN_BONE`/bone-hiding settings, Alex geometry.
- **Animated textures** (`three/animatedImage.ts`, `three/rig.ts`): nearly every Dawn texture is an animated WebP/AVIF (cloaks up to 60 frames, trims 3000). `decodeFrames` uses WebCodecs `ImageDecoder` to pack frames into a grid atlas <= 1024 px (`atlasLayout`: sampled evenly in time, halved in size while < 32 frames fit), with per-frame end times; without ImageDecoder it is the first frame. `rig.ts` (`buildRig`/`finish`, shared with Lunar) animates any `FrameLayout` grid (Lunar mcmeta strips are `stackedFrames`, 1 column; OBJ textures use `flipY`).
- `src/three/`: `geoModel.ts` (Bedrock geo → three groups with bones, per-cube epsilon inflate + polygonOffset to stop z-fighting), `animation/molang.ts` (small Molang interpreter incl. `lunar.*` from `cosmetics/functions.molang`; unknown identifiers evaluate to 0), `animation/bedrockAnim.ts` (keyframes may be `[..]`, `{pre,post}` or `{vector}`; a segment runs from a frame's `post` to the next frame's `pre`; GeckoLib `easing` (+`easingArgs` for step) applies to the segment ending at that keyframe; `lerp_mode: catmullrom`; without `animation_length` the length is the last keyframe; `hold_on_last_frame` doesn't loop; states seen: idle/moving/elytra/gui/walk/main; AnimationPlayer; states idle/moving/elytra/gui), `sharedRenderer.ts` (ONE WebGL canvas with per-card scissor viewports; camera near/far 1–12 for depth precision), `fit.ts`.
- `src/filtering.ts` (pure): `Rule`/`SortKey`, `applyView(items, search, rules, sorts, fieldDefs)`; missing values sort last; `encodeRules/decodeRules` (base64url tuples) and `encodeSorts/decodeSorts` for URLs. UI is `components/FilterBar.vue` (PrimeVue Popovers).
- Deep links: the grid mirrors `?q=&f=&s=&item=&cmp=` (ProviderView/CosmeticGrid use `router.replace`); the outfit page uses `?o=cat:id,...&e=emoteId`. The outfit tool page doesn't get q/f/s.
- `src/collections.ts`: named lists per provider (`assetviewer.collections.<provider>`, built-in `fav`), routes `/#/lunar/col-<id>` (mixed categories, union of fields). UI is `components/CollectionPicker.vue`: a bookmark button + count (`pi-bookmark`, `pi-bookmark-fill` once saved, `0` when none; no star icons) opening a Popover with search, checkboxes, saved lists first. On cards it sits top right (the shared canvas is stacked above the paint-contained cards, so `SharedRenderer` clears a 56x40 corner at the top right and 36x40 at the top left of every slot so this and the select checkbox show through), shows on hover, and stays visible with a filled bookmark once the item is in any collection; it is also before the modal title. A collection page has its own header bar above the toolbar (name, count, Rename/Delete/Export/Import). Selection mode (`src/selection.ts`, cards' top-left checkbox): the selection is cleared on category change; once non-empty, unselected cards are gray and the one toolbar also shows the count, Clear and Compare (2-4 items; opens `?cmp=`). There is ONE filter/sort bar. Only search hides items. Filter never hides: items in the *scope* (the selection if any, else everything shown) that pass move to the top and the failing ones are grayed (selected+passing = accent outline + color, selected but filtered out = dashed outline + gray, unselected = gray). Sort orders the scope (the selected cards reorder among their own grid slots). Export and Compare act on the scope items passing the filter (`actionItems` in `ProviderView`). `CompareDialog.vue` (one renderer, scissored panes, one shared camera and controls). Gray 3D thumbnails: the shared canvas can't be styled with CSS, so `SharedRenderer` renders `slot.gray` slots into a render target and draws them desaturated/translucent. `ExportButton.vue` (fflate async `zip`, images stored). `OutfitBuilder.vue` + `three/viewer.ts` (single-canvas viewer).
- `src/views/ProviderView.vue` (sidebar + toolbar + grid), `CosmeticModal.vue` (TrackballControls: drag rotates freely, Shift+drag or right-drag pans, wheel zooms; the "Free rotate" switch swaps in OrbitControls (upright, polar-clamped) live; help tooltip; two-column field list; Download dropdown; pin button), `CosmeticCard.vue`/`CosmeticGrid.vue`/`CosmeticList.vue`, `App.vue` (just the router view and the footer with stats from `src/stats.ts`).
- **Deployment**: it is a **Cloudflare Worker with static assets built by Workers Builds** (the GitHub check is "Workers Builds: assetviewer"), NOT Pages: a `functions/` dir is ignored. Every push to `main` runs `npm run build` and `wrangler deploy` with `wrangler.jsonc` (`dist` as assets, SPA not-found handling, `run_worker_first: ["/dawn/*"]`) and serves https://assetviewer.dreamys.studio (custom domain on the user's `dreamys.studio` zone). `PRIMEUI_LICENSE` is a build secret in the Cloudflare project settings. `public/_headers` sets immutable caching for hashed `/assets/*` and basic security headers. Hash routing. The Lunar CDN is fetched directly; `worker/index.ts` only proxies Dawn. Check a config change locally with `npm run build` then `npx wrangler@4 dev` (or `deploy --dry-run`).

## Gotchas learned the hard way
- **CORS/download errors**: a plain `<img>` (no `crossorigin`) caches a non-CORS response; a later `fetch()` of the same URL then fails. Adding `crossorigin` afterwards fails against that stale cache instead. Fix in place: images are fetched with `getFileBuffer` and shown from `blob:` URLs (`blobUrl` in `lunar/index.ts`); downloads use the hash cache (or `fetch(blob:)`). Don't reintroduce direct CDN `<img src>` or `fetch(url)` for downloads.
- **PrimeVue overlays inside a Popover**: Select/MultiSelect/DatePicker panels teleport to `body`, which the Popover treats as an outside click and closes. Use `append-to="self"` on every overlay component inside a Popover.
- **Animation state**: there is no grid-wide animation picker; the modal shows an "Animation" select only when a model has states besides idle/main (never for emotes). `loadGek` default state = `idle`, else the state-machine state with `plays_when: "1"`, else `main` (picking the first non-gui animation gave wrong poses and blank thumbnails).
- **Everything + list view**: the first sidebar entry is `everything` (label "Everything"): every item of every category (including the hidden emote resource categories), with a `category` field for filtering. The raw file browser (`FileBrowser.vue`) is no longer routed; `all-files` links redirect to `everything`. Every category has a grid/list toggle (`CosmeticList.vue` table: checkbox, name, category, type, file, size; persisted `assetviewer.view`; same selection/gray states; the zoom slider and Auto-rotate switch show in grid view only). Categories over `LAG_LIMIT` (500) items show a "may be laggy" banner.
- **Shared 3D toggles** (`src/viewPrefs.ts`): `autoRotate`, `wireframe`, `freeRotate` (default off = upright OrbitControls; on = TrackballControls) are persisted (`assetviewer.autoRotate|wireframe|freeRotate`) and shared by thumbnails (`SharedRenderer`), modal, compare dialog and outfit builder (`Viewer.setFreeRotate`, CompareDialog `makeControls`); the Auto-rotate switch sits in the toolbar right of the zoom slider. The modal applies the saved wireframe on open.
- **Theme** (`src/theme.ts`): `dark` ref toggles `.app-dark` on `<html>` (PrimeVue's `darkModeSelector`), persisted `assetviewer.theme`, defaulting to the OS preference. The sun/moon button sits at the bottom of the sidebar next to the player name. `--p-surface-N` does NOT flip with the theme, so components use the `--av-bg|card|border|hover|text|stage` tokens from `style.css` instead; never hard-code `--p-surface-*` in components.
- **Modal pin**: the thumbtack before the X makes the modal non-blocking (`pin-mask` class via `pt` on the mask, see-through and click-through; PrimeVue builds the modal mask at open, so toggling `:modal` alone doesn't change it). Clicking another card while pinned loads it into the same window. Closing unpins.
- **Download menu**: a model with a single source file downloads that file as is (no ZIP label); several files show `ZIP (.ext, ...)`; GLB is always offered for 3D.
- **Blank 3D thumbnails** usually mean an animation parse problem (a bone scale resolving to 0), not geometry. Reproduce at `/#/lunar/auras`.
- **Texture mirroring (`flipU`)**: the whole gek rig is mirrored (`scale.x` or `scale.z = -1`, see Facing), which also mirrors every face's artwork. `loadGek` builds with `buildGeoRig(geo, mat, flipU = true)`, which flips each face's u so the art reads the right way again. Without it, wings made of hinged strips whose art continues across the hinges (Butterfly Wings, Neon Wings, Easter Wings) showed each strip flipped in place and looked broken with gaps. `dragonWingGeo` and the cloak geometry are our own and tuned without it (cloaks aren't mirrored at all). For **per-face** UVs it is face-aware (`buildCube`): side faces flip u; up/down faces flip **v** instead (Blockbench writes Bedrock up/down UVs turned 180°; flipping u tore Dawn's cobweb/snowflake/ice dragon wings, whose art spans hinged flat planes); and `east`/`west` data trade sides (the rig is built in file space and mirrored afterwards, so "east" belongs on the -x face: Dawn's bat wings are x=0 planes with different art per side). Box UV keeps the plain u flip on every face.
- **Outlines around transparent faces**: `createMaterial` patches the Lambert shader: `vMapUv` uses `centroid` interpolation (with MSAA an edge pixel's centre can lie outside the triangle and its UV ran into the neighbouring atlas region: dotted outlines on wing membranes), and the alpha test reads the full-resolution texel (`texelFetch` level 0), since mipmapped alpha bleeds in neighbouring opaque texels once a big sheet is minified. Colour still comes from the mipmapped sample.
- **Z-fighting** comes from coplanar/overlapping Bedrock cubes + `DoubleSide`. Don't remove the per-cube inflate, polygonOffset, or tight near/far. `buildCube` drops faces with no texture area (edges of flat planes, faces left out of per-face UV): with the inflate they sampled one texel and outlined every flat part (wing feathers, sword flames) with a hairline square.
- **Vue setup order**: `watch(..., { immediate: true })` runs during setup; anything it touches (`const`/`let`) must be declared above it or you get a TDZ blank page.
- **Windows encoding**: the Write/Edit tools or a Python rewrite once left `src/App.vue` non-UTF-8 and Vite failed with "stream did not contain valid UTF-8". When doing Python rewrites use `open(p, encoding='utf-8')` and `newline=''`. To find a bad file: loop `iconv -f utf-8 -t utf-8` over `src`. Git's LF→CRLF warnings are harmless.
- Heredocs containing lots of quotes/backticks can break in Bash; use the Write tool for big files.
- Route ids are category ids, not labels (wings = `dragon_wings`, cloaks = `cloak`, auras = `auras`, hats = `hat`, pets = `pet`, `emotes`, `outfit`, `everything`, `col-fav`, etc.); an unknown id shows 0 items. `/#/lunar/<id>`.
- **Picker row order**: `CollectionPicker` fixes the row order *before* opening the popover; computing it in an after-show handler made rows visibly jump. Don't use a PrimeVue MultiSelect with custom `#value`/`#dropdownicon` slots as the trigger: it produced doubled/mixed icons.
- **Facing/handedness**: Bedrock geometry as `buildGeoRig` builds it is x-mirrored and faces -z (Blockbench negates x on import; e.g. the tuxedo tie is at z=-3.2, wings at z=+2). `loadGek`/`loadWing2d` fix this in a `prep` hook before fitting: `scale.x = -1` for the plain view (front towards the camera at -z), `scale.z = -1` in player space (the emote player faces +z, its right arm at -x). Forgetting this put ties on the back and wings in the stomach. OBJs and the emote player face +z; player views rotate by pi to show the face.
- **Dressing a player** (`lunar/dress.ts`): `biped*` bones (and `bipedRight/LeftItem`) are socketed to player bones; bones whose parent is missing from the file (`userData.missingParent`, e.g. a sword under `armorRightArm`) follow that parent's limb. Geks without biped bones use the gek's `attached_bone`: `HEAD` -> head, `SHOULDER` (pets) -> body, `RIGHT_ARM` (the wand) -> placed in the right hand. Unconditional `transformations` of type `rotate` are applied.
- **Skin outer layer**: the emote body mesh includes the second skin layer (head 8.8 px, limbs/torso 1.1x), while cosmetics are modelled around the base parts. `socket()` grows worn parts by `WORN_SCALE` (1.125) around each part's center (`PART_CENTER`), using the parent's pre-socket transform so nested biped bones aren't grown twice. Without it, hats, suits and glasses (lenses sit exactly at z = 4 px) were covered by the skin's second layer. Gek `hide_head|body|right_arm|left_arm|right_leg|left_leg` flags hide those player parts (`Player.hideParts`, drops body triangles by main bone), e.g. the robotic arm suit.
- **Thumbnail fit** (`visibleBox` in `fit.ts`): rigs are ticked to t=0 of their default animation before `fitObject`, and meshes that are hidden or collapsed to scale 0 don't count. Pets hide effects like a 100 px lightning bolt that way; fitting the static model made them tiny and off-center. Box faces only count their **opaque texels** (alpha >= 0.3 in any of up to 16 frames of an atlas; `opaqueBox` reads a <=512 px alpha mask of the texture via OffscreenCanvas, falls back to the geometry where pixels can't be read): flat wing membranes are big planes with the art in one corner and made wings (Christmas 2025) tiny.
- **Cloaks**: the design is the box's north face (OptiFine uv 1,1). No 180° turn: the plain view shows it towards the camera at -z, and on a player the cape hangs at z ≈ -3 with the design facing away from the back. With the turn both views showed the blank inner side.
- **Legacy OBJs come in three conventions** (`loadObj` sets `userData.objSpace` from the vertical center): `local` = y-down around the head center (hats) or neck/chest (bodywear; things that hang, like ties/necklaces, go to the neck and flat ones are pushed onto the chest front), `feet` = y-down in player space, `feet-up` = y-up in player space (no flip). Treating everything as `local` floated glasses two blocks above the head. Per-folder exceptions: `mask` is y-up (not flipped) and sits on nose/mouth, `bandanna` is turned -90° (tails to the back) and sits on the forehead, `facebandanna` sits lower (`HEAD_Y` in dress.ts); flat small bodywear (bow ties) goes just under the neck on the chest front.
- **Negative cube sizes**: some Bedrock models mirror a cube with negative `size` (paired with a plain copy that carries the other side's textures, e.g. the duck eyes); `buildCube` uses `Math.abs` for the box so each face texture stays on its own side (a negative BoxGeometry flipped them and left sides see-through). Slim skins still use the wide body (see-through arm strips are a known leftover; `emotes/models/entity/slim.bobj` shares the armature if you want to switch). The sidebar order is Everything, Cosmetics, Resources, Collections, Tools; grid auto-rotate is an accumulated angle in `SharedRenderer` so re-enabling resumes where it stopped.
- **Dragon wings** (`dragon_wings`, kind `wing2d`): the textures are ender dragon sheets (1024 = 256 grid x4), drawn on a built-in dragon wing model (`dragonWingGeo`: bone uv 112,88 + 56x56 membrane at -56,88, tip at 112,136 / -56,144) with a Molang flap. Membrane UVs follow Java box UV: outer end = u 0, bone edge = bottom of the quad (scallops on the top/trailing edge), left wing u-mirrored; getting this wrong put the scallops at the joints ("spliced rectangles"). Not the CDN's `simple_2d_wings` (that stretched the whole sheet over a plane). The pose is our own guess.
- **Outfit builder**: each slot row has a dice toggle (included in "Random"); exclusions persist in `assetviewer.outfit.random` so new slots start included. Random fills every included slot (3D items only) and leaves the others as they are. Keys are per provider: Lunar keeps `assetviewer.outfit` / `.outfit.random`, others use `assetviewer.outfit.<id>` / `.outfit.random.<id>`. The pose picker only shows when the provider has emotes.
- **Page metadata**: `index.html` has the title, description, theme-color, OG/Twitter tags (`og:image` = `/og.png`) and icons (`favicon.svg` cube, `favicon-32.png`, `apple-touch-icon.png`); canonical/og:url/og:image use the absolute production URL. `ProviderView` sets `document.title` per page (`<Category> · Asset Viewer`). The PNGs were rendered from the SVG with `_cdp.mjs` (inline the SVG markup on `about:blank`; an `<img>` there doesn't load).
- **Deep-linked modal**: `CosmeticModal` opens `props.item` in `onMounted` too; with only the watch, `?item=` links showed an empty modal.
- **three.js objects in Vue state** must stay out of deep reactivity: use `shallowRef` and replace whole arrays (CompareDialog panes), or keep them in plain `let`s.
- Synthetic `.click()` doesn't reliably select PrimeVue Select options: dispatch pointerdown/mousedown/pointerup/mouseup/click. For drags dispatch `PointerEvent`s (with `shiftKey` to pan) on the canvas.

## Verifying UI without a browser session
`scripts/_cdp.mjs` drives headless Chrome (swiftshader, so WebGL works but is slow, icon fonts may render as boxes):

```
node scripts/_cdp.mjs "<url>" "<wait JS (async ok, truthy to stop)>" "<JS whose value is printed>" "<screenshot.png>" [w] [h] [timeoutSeconds]
```

The wait expression must be an async IIFE `(async()=>{...; return true})()`; a bare top-level `await` silently fails and the run just times out. Dynamically importing `/src/...` modules in the page gives a **separate** module instance (Vite HMR timestamps), so set state by clicking the UI, not via imports. To check downloads, override `HTMLAnchorElement.prototype.click` to capture the blob href, then `import('/node_modules/.vite/deps/fflate.js')` to unzip. Typical flow: start `npx vite --port 5199` in the background, wait ~5 s, run the script with URL `http://localhost:5199/#/lunar/cloak`, a wait expression that does `await new Promise(r=>setTimeout(r,5000))` then clicks things (`document.querySelector('.card').click()`, find buttons by `innerText`), then view the PNG with Read. Set `LOGS=1` to echo console output. Keep a single run under ~100 s (tool timeout is 120 s); kill node afterwards. Synthetic `.click()` works for PrimeVue buttons/options; for stubborn ones dispatch pointer/mouse events too. Real-GPU smoothness and drag interaction can't be verified this way — say so rather than claiming it.

## Conventions
- **Prompts**: never use the browser's `prompt`/`confirm`/`alert`. `src/dialogs.ts` (`askText`, `askConfirm`, `notify`) drives the one `components/AppDialog.vue` mounted in `App.vue` (title with icon, `warn`/`danger` tones, Enter submits, `remember` adds a "Don't ask again" box stored under that localStorage key). The text input needs the `autofocus` attribute: PrimeVue's Dialog focuses `[autofocus]` on open and otherwise takes focus back to its own button. Clicking Everything in the sidebar asks first (`openEverything`, key `assetviewer.skipEverythingWarning`); direct links don't.
- **Uniform UI**: toolbar/action buttons are `size="small" severity="secondary"` (filled grey, no accent colour); only confirm buttons inside dialogs/popovers (Add filter, Export) and the preview's Download + Copy link stay primary. A popup `Menu` must not sit inside a flex row with a gap (its placeholder adds a second gap). A button that opens a menu or popover ends with `<i class="pi pi-chevron-down chev" />` (Filter, Sort, Download). Icon + text pairs use the global `.icon-text` class (inline-flex, centred) so icons never sit above the text. Counts go through `plural()` ("1 item"). The provider switcher is deliberately different. The footer is three equal centred sections (disclaimer, stats, GitHub).
- Match surrounding style: no semicolons, single quotes, 2-space indent, short comments explaining *why*.
- New fields for filtering: add to `CosmeticItem.fields` (catalog or `enrich()`), then expose in `lunarProvider.fields()` and, if user-visible, in `info()`.
- Persisted UI prefs use `localStorage` inside try/catch (`assetviewer.cols`, `assetviewer.sort.<provider>.<category>`).
- Unpushed work stays committed locally; the user asks for pushes explicitly (often as "commit and push it" after reviewing a change). Offer to commit when a change is done and tested.
- Known leftovers: main chunk ~1.5 MB; `moving`/`elytra` animations run with zero-speed inputs; emote particle collision/lighting, `blockbuster:particle_morph` and slim arms aren't rendered; vanilla block/item particle textures (dirt, snow, snowball) are drawn as plain tinted squares; older (`local`) OBJ placement on the player is heuristic; the wand's in-hand pose and the dragon wing pose are guesses; 9 newest emotes have no icon (name tile).
