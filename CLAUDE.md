# Asset Viewer — working notes for Claude

Unofficial fan viewer for Lunar Client cosmetics, served from `https://textures.lunarclientcdn.com` (CORS `*`). Vue 3 + Vite 8 + vue-router (hash history) + PrimeVue 5 (Aura, `.app-dark`) + three.js 0.186. There is no top bar: the sidebar (in `ProviderView.vue`) holds the big provider switcher (`ProviderSwitch.vue`, a popover with multiline options; Lunar Client / Essential, the latter a "coming soon" stub in `providers/essential.ts`), the category menu, and at the bottom `SideControls.vue` (player name + theme). `/#/lunar` redirects to the `home` pseudo-category (`HomeView.vue`: title, stats, category links, tips, credits), which is not in `provider.categories()`; the menu adds a Home entry before Everything.

## Rules
- **`.env` holds `PRIMEUI_LICENSE`.** It must stay git-ignored. Never print, echo or commit it. (It ends up in the built JS; unavoidable for a client app.)
- Commit trailer: `Co-Authored-By: Claude <model> <noreply@anthropic.com>` naming the model actually in use (e.g. `Claude Opus 5.5`); follow the attribution reminder in the session if one is given. PR bodies end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- Only commit/push when asked. The user typically says "commit and push"; commit locally and offer to push otherwise.
- Pronouns: they/them unless stated.
- Shell is Windows (Git Bash/PowerShell). Use Unix syntax in Bash. Don't run `sleep` chains in the foreground.

## Commands
- `npm run dev` (vite; I use `npx vite --port 5199`), `npm run build` (= `vue-tsc -b && vite build`). The build always prints a >500 kB chunk warning (known, ignorable).
- Type check alone: `npx vue-tsc -b` (silent = pass). `erasableSyntaxOnly` is on: no class parameter properties.
- `node scripts/coverage.mjs` — classifies every CDN index file as item / dependency / resource and must print `UNCLAIMED 0` (exit 1 otherwise). Run it after touching `lunar/catalog.ts`.
- `taskkill //F //IM node.exe` stops stray dev servers/CDP runs (Git Bash needs the double slashes).

## Architecture
- `src/cdn.ts`: `getIndexBuffer`, `getFileBuffer/Json/Text(hash)`, `fileUrl(hash)`. Everything on the CDN is content-hash addressed, so results are stored in Cache Storage forever (`assetviewer-cdn-v1`) with a retry/backoff fetch. **Always get bytes through this cache** (see CORS notes).
- `src/providers/types.ts`: `CosmeticProvider` interface (`categories`, `fields(category)`, `items`, `imageUrl`, `loadModel`, `rawFile`, `indexedFiles`, `fileItem`, `ensureDimensions`, `info`, `stats`). `CosmeticItem.fields` is the bag the filter/sort bar reads; `name` is read from `item.name`.
- `src/providers/lunar/catalog.ts` builds the catalog from the two root indexes (`LUNAR_INDEXES` in `config.ts`; text lines `path sha1 size mtime`): `cosmetics.json` (primary), the legacy CSV `cosmetics/index` (fills gaps, typo'd ids), badges/sprays/emotes/particles/misc as "resources", and any unlisted cosmetic files found by scanning, plus one `emote` entry per `emotes/emotes.json` emote (category `emotes`; pushed without claiming paths so the emote files stay listed as resources). `Kind` = `gek | obj | wing2d | cloak | emote | image | file`. `CosmeticItem.thumb` ('image' | 'none') lets a 3D item (emotes) show its icon/name on the card instead of a live model.
- `src/providers/lunar/index.ts`: the provider. `loadGek` (Bedrock `.geo.json` + `.anim.json` + texture), `loadWing2d` (flat wing webp on `simple_2d_wings.geo.json`), `loadCloak` (22×17 OptiFine cape layout, scaled by any integer; stacked frames for animated), `loadObj` (legacy OBJ hats). `enrich()` adds id/path/folder/ext/size/type/model fields; `ownerOf()` maps any file path to its owning item (used by All files). Dimensions are measured lazily from file headers via Range requests (`src/dimensions.ts`). `loadModel(item, { raw: true })` skips `fitObject` (player-space blocks) for dressing a player; `sourceFiles`/`estimateSize` feed the ZIP export; `itemById` serves deep links/collections.
- Emotes (`lunar/emotes.ts`, `three/bobj.ts`): McHorse "Blockbuster OBJ" text. `arm_bone name parent tailX tailY tailZ <16 floats row-major head matrix>` (root parent is an empty token: split on single spaces), `o/v/vw/vt/vn/f` skinned meshes (OBJ indices are file-wide; flip `v`), actions `an/ao/ag location|rotation|scale axis/kf tick value BEZIER|LINEAR|SINE|CONSTANT lx ly rx ry` in ticks (20/s). Pose = `inv(parent.mat)·mat · T · R(Euler 'ZYX' = Blender XYZ) · S`, bones written to `bone.matrix` (matrixAutoUpdate off) and bound as a three `SkinnedMesh` (bind matrix identity, bones under the body mesh). Body = `emotes/models/entity/default.bobj`; emote `x` plays action `emote_x`, found by scanning the 9 actions files (one is 16 MB; `extractAction` slices one block); props from `emotes.json.props` **plus `props.bobj` (missing from that list)**, textures from `emotes.json.meshes` **or `entity/default.json` meshes** (popcorn); `meshes[].show_at` = tick a prop appears. `LoadedModel.timeline` drives play/pause/scrub.
- Emote particles (`three/particles.ts`, `emoteEffects` in `lunar/emotes.ts`): an emote's `morph` names an entry in `particles/configuration.json` whose `morphs[]` give `{Scheme:"x"}` (a Bedrock `particles/schemes/x.particle.json`), a player bone, `start`/`length` (ticks) and a translate/rotation/scale; `particleEffect` (make_it_rain) uses the scheme's own bone. `Emitter` simulates one scheme (steady/instant rate, point/disc/sphere/box shapes, dynamic/parametric motion, flipbook UVs, tint gradients, catmull-rom curves, Molang via `molang.ts` with `variable.particle_*`/`emitter_*`) and draws camera-facing quads with a tiny shader (offset scaled by the object's scale; sizes are half-extents). Texture `textures/particle/particles` = `particles/textures/default_particles.webp` (128x128; `emotes/textures/particles.webp` is a 78-byte stub). Particles are children of `player.object` and follow bones via `bone.matrixWorld`; jumps/loops of the emote tick reset them.
- Player (`three/player.ts`, `lunar/dress.ts`, `src/skin.ts`): the emote body in blocks. `dressPlayer(items, emote?)` adds raw cosmetics and "sockets" every gek group named `biped(Head|Body|RightArm|LeftArm|RightLeg|LeftLeg)*` under the matching player bone (a fixed holder reproduces its rest parent, so gek animations keep working; arm/leg side chosen by pivot x since some models mirror). Cloaks use `CAPE_ON_PLAYER` (bone `bipedBody`), OBJ hats/bodywear are placed by a heuristic (head/chest center, hats fully above center lifted onto the head). Skin: procedural placeholder, or `https://mc-heads.net/skin/<name>` (CORS *), persisted `assetviewer.skin`. It is one global "Player name" input at the bottom of the sidebar (`components/SideControls.vue`); the modal and the outfit builder watch `skinName` and redraw.
- `src/three/`: `geoModel.ts` (Bedrock geo → three groups with bones, per-cube epsilon inflate + polygonOffset to stop z-fighting), `animation/molang.ts` (small Molang interpreter incl. `lunar.*` from `cosmetics/functions.molang`; unknown identifiers evaluate to 0), `animation/bedrockAnim.ts` (keyframes may be `[..]`, `{pre,post}` or `{vector}`; states seen: idle/moving/elytra/gui/walk/main; AnimationPlayer; states idle/moving/elytra/gui), `sharedRenderer.ts` (ONE WebGL canvas with per-card scissor viewports; camera near/far 1–12 for depth precision), `fit.ts`.
- `src/filtering.ts` (pure): `Rule`/`SortKey`, `applyView(items, search, rules, sorts, fieldDefs)`; missing values sort last; `encodeRules/decodeRules` (base64url tuples) and `encodeSorts/decodeSorts` for URLs. UI is `components/FilterBar.vue` (PrimeVue Popovers).
- Deep links: the grid mirrors `?q=&f=&s=&item=&cmp=` (ProviderView/CosmeticGrid use `router.replace`); the outfit page uses `?o=cat:id,...&e=emoteId`. The outfit tool page doesn't get q/f/s.
- `src/collections.ts`: named lists per provider (`assetviewer.collections.<provider>`, built-in `fav`), routes `/#/lunar/col-<id>` (mixed categories, union of fields). UI is `components/CollectionPicker.vue`: a bookmark button + count (always `pi-bookmark`, `0` when none; no star icons) opening a Popover with search, checkboxes, saved lists first. It lives on card hover and before the modal title. Selection mode (`src/selection.ts`, cards' top-left checkbox): the selection is cleared on category change; once non-empty, unselected cards are gray and the one toolbar also shows the count, Clear and Compare (2-4 items; opens `?cmp=`). There is ONE filter/sort bar. Only search hides items. Filter never hides: items in the *scope* (the selection if any, else everything shown) that pass move to the top and the failing ones are grayed (selected+passing = accent outline + color, selected but filtered out = dashed outline + gray, unselected = gray). Sort orders the scope (the selected cards reorder among their own grid slots). Export and Compare act on the scope items passing the filter (`actionItems` in `ProviderView`). `CompareDialog.vue` (one renderer, scissored panes, one shared TrackballControls camera). Gray 3D thumbnails: the shared canvas can't be styled with CSS, so `SharedRenderer` renders `slot.gray` slots into a render target and draws them desaturated/translucent. `ExportButton.vue` (fflate async `zip`, images stored). `OutfitBuilder.vue` + `three/viewer.ts` (single-canvas viewer).
- `src/views/ProviderView.vue` (sidebar + toolbar + grid), `CosmeticModal.vue` (TrackballControls: drag rotates freely, Shift+drag or right-drag pans, wheel zooms; the "Free rotate" switch swaps in OrbitControls (upright, polar-clamped) live; help tooltip; two-column field list; Download dropdown; pin button), `CosmeticCard.vue`/`CosmeticGrid.vue`/`CosmeticList.vue`, `App.vue` (header with the global player name; footer with stats from `src/stats.ts`).
- `worker/`: optional Cloudflare Worker proxy; deploy is the user's step (`VITE_CDN_BASE` points the app at it).

## Gotchas learned the hard way
- **CORS/download errors**: a plain `<img>` (no `crossorigin`) caches a non-CORS response; a later `fetch()` of the same URL then fails. Adding `crossorigin` afterwards fails against that stale cache instead. Fix in place: images are fetched with `getFileBuffer` and shown from `blob:` URLs (`blobUrl` in `lunar/index.ts`); downloads use the hash cache (or `fetch(blob:)`). Don't reintroduce direct CDN `<img src>` or `fetch(url)` for downloads.
- **PrimeVue overlays inside a Popover**: Select/MultiSelect/DatePicker panels teleport to `body`, which the Popover treats as an outside click and closes. Use `append-to="self"` on every overlay component inside a Popover.
- **Animation state**: there is no grid-wide animation picker; the modal shows an "Animation" select only when a model has states besides idle/main (never for emotes). `loadGek` default state = `idle`, else the state-machine state with `plays_when: "1"`, else `main` (picking the first non-gui animation gave wrong poses and blank thumbnails).
- **Everything + list view**: the first sidebar entry is `everything` (label "Everything"): every item of every category (including the hidden emote resource categories), with a `category` field for filtering. The raw file browser (`FileBrowser.vue`) is no longer routed; `all-files` links redirect to `everything`. Every category has a grid/list toggle (`CosmeticList.vue` table: checkbox, name, category, type, file, size; persisted `assetviewer.view`; same selection/gray states; the zoom slider and Auto-rotate switch show in grid view only). Categories over `LAG_LIMIT` (500) items show a "may be laggy" banner.
- **Shared 3D toggles** (`src/viewPrefs.ts`): `autoRotate`, `wireframe`, `freeRotate` are persisted (`assetviewer.autoRotate|wireframe|freeRotate`) and shared by thumbnails (`SharedRenderer`), modal, compare dialog and outfit builder; the Auto-rotate switch sits in the toolbar right of the zoom slider. The modal applies the saved wireframe on open.
- **Theme** (`src/theme.ts`): `dark` ref toggles `.app-dark` on `<html>` (PrimeVue's `darkModeSelector`), persisted `assetviewer.theme`, defaulting to the OS preference. The sun/moon button sits at the bottom of the sidebar next to the player name. `--p-surface-N` does NOT flip with the theme, so components use the `--av-bg|card|border|hover|text|stage` tokens from `style.css` instead; never hard-code `--p-surface-*` in components.
- **Modal pin**: the thumbtack before the X makes the modal non-blocking (`pin-mask` class via `pt` on the mask, see-through and click-through; PrimeVue builds the modal mask at open, so toggling `:modal` alone doesn't change it). Clicking another card while pinned loads it into the same window. Closing unpins.
- **Download menu**: a model with a single source file downloads that file as is (no ZIP label); several files show `ZIP (.ext, ...)`; GLB is always offered for 3D.
- **Blank 3D thumbnails** usually mean an animation parse problem (a bone scale resolving to 0), not geometry. Reproduce at `/#/lunar/auras`.
- **Z-fighting** comes from coplanar/overlapping Bedrock cubes + `DoubleSide`. Don't remove the per-cube inflate, polygonOffset, or tight near/far. `buildCube` drops faces with no texture area (edges of flat planes, faces left out of per-face UV): with the inflate they sampled one texel and outlined every flat part (wing feathers, sword flames) with a hairline square.
- **Vue setup order**: `watch(..., { immediate: true })` runs during setup; anything it touches (`const`/`let`) must be declared above it or you get a TDZ blank page.
- **Windows encoding**: the Write/Edit tools or a Python rewrite once left `src/App.vue` non-UTF-8 and Vite failed with "stream did not contain valid UTF-8". When doing Python rewrites use `open(p, encoding='utf-8')` and `newline=''`. To find a bad file: loop `iconv -f utf-8 -t utf-8` over `src`. Git's LF→CRLF warnings are harmless.
- Heredocs containing lots of quotes/backticks can break in Bash; use the Write tool for big files.
- Route ids are category ids, not labels (wings = `dragon_wings`, cloaks = `cloak`, auras = `auras`, hats = `hat`, pets = `pet`, `emotes`, `outfit`, `everything`, `col-fav`, etc.); an unknown id shows 0 items. `/#/lunar/<id>`.
- **Picker row order**: `CollectionPicker` fixes the row order *before* opening the popover; computing it in an after-show handler made rows visibly jump. Don't use a PrimeVue MultiSelect with custom `#value`/`#dropdownicon` slots as the trigger: it produced doubled/mixed icons.
- **Facing/handedness**: Bedrock geometry as `buildGeoRig` builds it is x-mirrored and faces -z (Blockbench negates x on import; e.g. the tuxedo tie is at z=-3.2, wings at z=+2). `loadGek`/`loadWing2d` fix this in a `prep` hook before fitting: `scale.x = -1` for the plain view (front towards the camera at -z), `scale.z = -1` in player space (the emote player faces +z, its right arm at -x). Forgetting this put ties on the back and wings in the stomach. OBJs and the emote player face +z; player views rotate by pi to show the face.
- **Dressing a player** (`lunar/dress.ts`): `biped*` bones (and `bipedRight/LeftItem`) are socketed to player bones; bones whose parent is missing from the file (`userData.missingParent`, e.g. a sword under `armorRightArm`) follow that parent's limb. Geks without biped bones use the gek's `attached_bone`: `HEAD` -> head, `SHOULDER` (pets) -> body, `RIGHT_ARM` (the wand) -> placed in the right hand. Unconditional `transformations` of type `rotate` are applied.
- **Skin outer layer**: the emote body mesh includes the second skin layer (head 8.8 px, limbs/torso 1.1x), while cosmetics are modelled around the base parts. `socket()` grows worn parts by `WORN_SCALE` (1.125) around each part's center (`PART_CENTER`), using the parent's pre-socket transform so nested biped bones aren't grown twice. Without it, hats, suits and glasses (lenses sit exactly at z = 4 px) were covered by the skin's second layer. Gek `hide_head|body|right_arm|left_arm|right_leg|left_leg` flags hide those player parts (`Player.hideParts`, drops body triangles by main bone), e.g. the robotic arm suit.
- **Thumbnail fit** (`visibleBox` in `fit.ts`): rigs are ticked to t=0 of their default animation before `fitObject`, and meshes that are hidden or collapsed to scale 0 don't count. Pets hide effects like a 100 px lightning bolt that way; fitting the static model made them tiny and off-center.
- **Cloaks**: the design is the box's north face (OptiFine uv 1,1). No 180° turn: the plain view shows it towards the camera at -z, and on a player the cape hangs at z ≈ -3 with the design facing away from the back. With the turn both views showed the blank inner side.
- **Legacy OBJs come in three conventions** (`loadObj` sets `userData.objSpace` from the vertical center): `local` = y-down around the head center (hats) or neck/chest (bodywear; things that hang, like ties/necklaces, go to the neck and flat ones are pushed onto the chest front), `feet` = y-down in player space, `feet-up` = y-up in player space (no flip). Treating everything as `local` floated glasses two blocks above the head. Per-folder exceptions: `mask` is y-up (not flipped) and sits on nose/mouth, `bandanna` is turned -90° (tails to the back) and sits on the forehead, `facebandanna` sits lower (`HEAD_Y` in dress.ts); flat small bodywear (bow ties) goes just under the neck on the chest front.
- **Negative cube sizes**: some Bedrock models mirror a cube with negative `size` (paired with a plain copy that carries the other side's textures, e.g. the duck eyes); `buildCube` uses `Math.abs` for the box so each face texture stays on its own side (a negative BoxGeometry flipped them and left sides see-through). Slim skins still use the wide body (see-through arm strips are a known leftover; `emotes/models/entity/slim.bobj` shares the armature if you want to switch). The sidebar order is Everything, Cosmetics, Resources, Collections, Tools; grid auto-rotate is an accumulated angle in `SharedRenderer` so re-enabling resumes where it stopped.
- **Dragon wings** (`dragon_wings`, kind `wing2d`): the textures are ender dragon sheets (1024 = 256 grid x4), drawn on a built-in dragon wing model (`dragonWingGeo`: bone uv 112,88 + 56x56 membrane at -56,88, tip at 112,136 / -56,144) with a Molang flap. Membrane UVs follow Java box UV: outer end = u 0, bone edge = bottom of the quad (scallops on the top/trailing edge), left wing u-mirrored; getting this wrong put the scallops at the joints ("spliced rectangles"). Not the CDN's `simple_2d_wings` (that stretched the whole sheet over a plane). The pose is our own guess.
- **Deep-linked modal**: `CosmeticModal` opens `props.item` in `onMounted` too; with only the watch, `?item=` links showed an empty modal.
- **three.js objects in Vue state** must stay out of deep reactivity: use `shallowRef` and replace whole arrays (CompareDialog panes), or keep them in plain `let`s.
- Synthetic `.click()` doesn't reliably select PrimeVue Select options: dispatch pointerdown/mousedown/pointerup/mouseup/click. For drags dispatch `PointerEvent`s (with `shiftKey` to pan) on the canvas.

## Verifying UI without a browser session
`scripts/_cdp.mjs` drives headless Chrome (swiftshader, so WebGL works but is slow, icon fonts may render as boxes):

```
node scripts/_cdp.mjs "<url>" "<wait JS (async ok, truthy to stop)>" "<JS whose value is printed>" "<screenshot.png>" [w] [h] [timeoutSeconds]
```

The wait expression must be an async IIFE `(async()=>{...; return true})()`; a bare top-level `await` silently fails and the run just times out. Dynamically importing `/src/...` modules in the page gives a **separate** module instance (Vite HMR timestamps), so set state by clicking the UI, not via imports. To check downloads, override `HTMLAnchorElement.prototype.click` to capture the blob href, then `import('/node_modules/.vite/deps/fflate.js')` to unzip. Typical flow: start `npx vite --port 5199` in the background, wait ~5 s, run the script with URL `http://localhost:5199/#/lunar/cloak`, a wait expression that does `await new Promise(r=>setTimeout(r,5000))` then clicks things (`document.querySelector('.card').click()`, find buttons by `innerText`), then view the PNG with Read. Set `LOGS=1` to echo console output. Keep a single run under ~100 s (tool timeout is 120 s); kill node afterwards. Synthetic `.click()` works for PrimeVue buttons/options; for stubborn ones dispatch pointer/mouse events too. Real-GPU smoothness and drag interaction can't be verified this way — say so rather than claiming it.

## Conventions
- Match surrounding style: no semicolons, single quotes, 2-space indent, short comments explaining *why*.
- New fields for filtering: add to `CosmeticItem.fields` (catalog or `enrich()`), then expose in `lunarProvider.fields()` and, if user-visible, in `info()`.
- Persisted UI prefs use `localStorage` inside try/catch (`assetviewer.cols`, `assetviewer.sort.<provider>.<category>`).
- Unpushed work stays committed locally; the user asks for pushes explicitly (often as "commit and push it" after reviewing a change). Offer to commit when a change is done and tested.
- Known leftovers: main chunk ~1.5 MB; `moving`/`elytra` animations run with zero-speed inputs; Worker deploy is manual; emote particle collision/lighting, `blockbuster:particle_morph` and slim arms aren't rendered; vanilla block/item particle textures (dirt, snow, snowball) are drawn as plain tinted squares; older (`local`) OBJ placement on the player is heuristic; the wand's in-hand pose and the dragon wing pose are guesses; 9 newest emotes have no icon (name tile).
